# html-note — 長結論不要倒進聊天視窗

## 為什麼有這支

一份分析做完，六十行結論貼進對話——**看起來交付了，其實沒有**。

- 對方常在手機或平板上看，長訊息滑不動、抓不到重點。
- 隔天想回頭找，在對話紀錄裡翻不到。
- 而且**不會有人告訴你「我沒看」**，你會以為講完了。

所以規則很簡單：**超過 30 行的交付物，一律變成一頁網頁，對話裡只回連結（或檔案路徑）加三行重點。**

## 什麼算「交付物」

會，就走這支：分析、體檢報告、計畫書、盤點、比較表、審查意見、驗收報告、決策材料。

不會：程式碼、給機器讀的中繼檔、三五行就講得完的答覆。

---

## 流程

### 1. 寫成一頁 HTML

- **結論先行**：開頭就是「三行重點」，細節放後面。**不要讓人讀到第三段才知道結論。**
- 單欄、`max-width` 約 720px、字級 15px 以上——手機與平板直接可讀。
- 語氣白話。技術名詞保留原文 inline，不要硬翻。
- 表格、程式碼區塊要能在自己的容器內橫向捲動，**頁面本身不可以左右晃**。
- 檔名 kebab-case、帶日期、不含空格：`<主題>-<YYYYMMDD>.html`。

### 2. **一定要有「要你決定什麼」那一段**

這是最常被漏掉、也最影響對方體驗的一段。每一頁開頭都要明確二選一：

- **「現在球在你這裡的是：X」** ＝ 需要對方決定或動手
- **「不需要你做事，只是回報：Y」** ＝ 純進度

沒有這一段，讀的人得自己讀完全文才知道要不要停下來處理。

### 3. 交付：預設存本機直接開，要給不在旁邊的人才發佈

**預設做法不需要任何帳號、額度或發佈管道：HTML 存在本機，直接用瀏覽器開**，
或把那個單一 HTML 檔傳給對方——單檔全內聯，收到點兩下就能看。

**只有「對方不在旁邊、要一個點了就能看的連結」才需要發佈成網址。**
這時**先問使用者手上有什麼管道**（自架靜態站、內部檔案伺服器、公司現成的託管都行）——
不要假設他有，也不要替他挑一個要註冊帳號或花錢的服務。

> 想要一個常駐的私人發佈站的話，同一個 marketplace 裡的 **`tailscale-preview-site`** 是一種做法：
> 用一台常開的機器 + Tailscale 私網架一個只有自己看得到的站，一行指令發佈。
> **那是選配，不是這支 skill 的前提。**

**有發佈的話，跨環境成立的兩條紀律：**

- **同一份東西改版要回到同一個網址。** 每改一版換一個連結，對方會分不清哪個是最新的。
- **改完之後在網址後面加 `?v=2` 之類的參數**，否則對方的瀏覽器給他舊版，他會以為你沒改。

### 4. 回覆的格式

```
<一句話結論>
<網址或檔案路徑>
- 重點 1
- 重點 2
- 重點 3
```

只給連結（或本機檔案路徑）加三行重點。對方說「直接貼給我看」才把全文貼進對話。

## 配一個機器層的提醒（重點）

**這支真正有效的原因不是「有規矩」，是「不靠人記得」。**

掛一個 hook：偵測到寫出「看起來像交付物的檔案」（放在交付用的資料夾、
或檔名含報告／計畫／盤點／審查／評估／分析／結論／決策等字），就當場注入提醒走這條路。
每個對話提醒一次就好，不要變成雜訊。

**逃生門**：把那條 hook 從設定裡拿掉即可。任何守衛都要有逃生門，湊不出來的就不該存在。

## 別做的事

- **不要自動把筆記變成投影片。** 流程走到「下一步是簡報」時先問，同意了才做。
- **不要重建整份索引頁**（如果你有一頁清單）——那通常是人工策展的，重建會毀掉既有文案。
- 不要把交付物目錄放進作業系統的保護區（macOS 的桌面／文件夾），
  背景程序會讀不到，而你會花很久才想到是權限問題。

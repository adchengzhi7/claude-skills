# tune-flow

Claude Code skill：每月一次的工作流程健檢：從實際紀錄抓摩擦，派三個立場對立的角色辯論，收斂成清單等人拍板，決策留檔避免重蹈。

## 解決什麼問題

摩擦是慢性的：每次只浪費十分鐘，所以每次都覺得「算了下次再說」。

更糟的是**修完沒人回頭看有沒有效**——裝了防護，沒人知道它根本沒啟動。
代價是「以為有的防護其實不存在」，而你要等到出事才知道。

## 怎麼解

1. **訊號源用實際紀錄，不用印象**——機制自己的 log、工作筆記、使用者口述的痛點
2. **派三個立場對立的角色**：代表使用者的（按爆炸半徑排優先）、熟工具的（找最省力修法，並主動說哪些不該做）、專門挑毛病的（不提方案，只質疑數字）
3. **中間一定停下來等人勾選**——人決定做不做，skill 只負責找出該做什麼並證明做得對
4. **每個提案要附三樣**：用什麼機制、測試怎麼跑、逃生門是什麼。湊不出逃生門的守衛不該存在
5. **決策留檔**：緩的記重啟條件、不做的記原因——下次跑之前先讀，同一個爛點子不會又被提一遍

## 用法

安裝後，在對話裡講出觸發語即可：

```
檢討一下流程 / 優化工作流程 / 我一直撞到 X / 月度回顧
```

## 建議當範本改，不要照抄

這支是從真實工作長出來的，裡面的「踩過的雷」有些直接通用
（例如「只端一個方案等於替人做決定」），有些綁定特定工具，請換成你自己的。

**skill 真正值錢的不是步驟，是雷。** 步驟誰都想得到，雷想不到。

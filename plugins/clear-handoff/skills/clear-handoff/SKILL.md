# clear-handoff — /clear 前的交接打包

使用者長 session 做到一半、要 /clear 釋放 context、等下回來繼續。
你的工作：**把「現在做到哪、下一步做什麼、東西在哪、有什麼雷」固化成檔，並交給使用者可直接貼回的 prompt。**

目標：使用者 clear 完，貼一條 prompt（或打「繼續 X」），新 context 就能無縫接上，不用重新摸索。

---

## 執行步驟

### 0. 先確認筆記的家在哪（本機照舊、雲端要問）
- 跑在使用者自己的機器（本機安裝的 Claude Code）→ 筆記照舊寫 `~/.claude/sessions/`，不用問，直接往下。
- 跑在雲端 container（Cowork、claude.ai/code 雲端 session、CI 這類用完即丟的環境）→ `~/.claude/sessions/` 會隨 container 回收一起消失，**不能當落點**。先問使用者一次存哪。
- 判斷不了自己在哪 → 當作雲端處理（寧可多送一份檔案，不要少一份筆記）。

**問法照這個模板**——先用白話講清楚發生什麼事（別假設使用者知道 container 是什麼），選項附**實際路徑**，並讓使用者能自己指定：

> 提醒一下：這個 session 跑在雲端的暫時環境，我平常存交接筆記的地方會在環境回收時**跟著消失**，所以這次筆記要換個地方放。你想存哪？
> - **A（建議）：直接把筆記檔傳到這個對話裡**，你自己保管，最保險
> - B：存進目前的專案資料夾（實際位置：`{列出真實路徑，如 ~/專案/.claude/sessions/2026-08-24-xxx.tmp}`）——下次好接，但筆記會跟專案放一起，要進 repo 我 commit 前會再問你
> - C：你說一個路徑，我存那裡

A＝把檔案直接傳到對話裡（如 SendUserFile）；B＝寫檔（要 commit 先問）；C＝寫使用者給的路徑並複述一次確認。

選 B 但雲端根本沒有已連接的資料夾（Cowork 常見）→ 先請使用者授權／連接一個資料夾（用當下環境提供的授權機制，講行為不寫死工具名）；拿不到或被拒 → 退回 A 傳檔案，**不要卡住收尾**。

### 1. 盤點當前工作狀態（從對話，不靠 git）
釐清並寫下：
- **正在做的任務 + 做到哪**（已完成 / 進行中）
- **▶ 立即下一步**：clear 後第一件要做的事，要具體到「動哪個檔、跑哪個指令」
- **相關檔案/路徑**：工作檔、產出物、設定、素材的絕對或專案相對路徑
- **關鍵決策**：已拍板的方向（避免下次重議）
- **待辦清單**：剩下的事，按優先序
- **環境雷**：
  - **這個 session 跑在哪台機器？**（`hostname`）—— 若不是使用者面前那台，記下「`open` 會開錯機器、要改用 http server / 檔案同步」這類雷
  - 認證 / token / 測試帳號怎麼取得（只記「去哪拿」，**不記明文 secret**）

### 2. 掃背景程序（/clear 不會停它們，但新 context 不知道它在跑）
- 找出還在跑的 server / background task（port、用途）
- 判斷 clear 後還需不需要：需要 → 記進 note（含怎麼確認還活著、怎麼重開）；不需要 → 提醒使用者可關

### 3. 寫 / 更新 session note
- 路徑：`~/.claude/sessions/{YYYY-MM-DD}-{HHmm}-{專案簡稱}.tmp`（同日多 session 用時間戳區分，不要覆蓋；目錄不存在先建；**雲端環境改用步驟 0 選定的落點**）
- 檔頭放 **▶ RESUME POINT / 立即下一步**，最顯眼
- **超過約 150 行就開新檔**，舊檔尾巴寫一行「本 note 到此結案，接 ⟨新檔名⟩」——別把一份筆記養成 400 行的滾動日誌
- 內容＝步驟 1-2 全部，寫成「別人接手也看得懂」

**建議骨架——分隔線之上會過期、之下要能留**：

```markdown
# {專案} — {一句話：這次在幹嘛}

## ▶ 立即下一步
## 狀態與待辦
## 環境與背景程序

---
<!-- 以下：任務結束後仍然有價值 -->

## 耐久：設計決定與理由
## 耐久：踩到的雷
```

判準（重點在判準不在格子）：
- 進上半部：**這個任務收掉後，這一行還有意義嗎？沒有 → 上半部**（branch 名、PR 編號、做到第幾步、開著的 port）
- 進「耐久」的四類：**不可逆操作的防護設計**（含為什麼刻意不加重試、批次上限）／**刻意不做、不動的事**（`git diff` 看不到「沒改的東西」，最容易流失）／反直覺的環境事實／**否決過的方案**（試過 A 不行因為 B）
- **不要進耐久：讀 code 十分鐘能自己搞懂的事。** 耐久格只放 code 裡看不到的——這條同時擋住耐久格爆炸
- 每條寫成 `- {結論}｜因為 {理由}｜{檔案路徑或指令}`。**沒有「因為」就不是知識，是流水帳**

### 4. 更新 memory（只有「之後還會回來做的真專案」才寫，且你有啟用 Claude 的記憶機制）
- **測試、示範、一次性任務、假資料一律不寫**；不確定是哪種 → 不寫（或問一句），寧缺勿濫——寫錯一筆假專案進 memory，比少寫一筆貴得多
- 在該專案的 memory 檔補一行 **▶ RESUME POINT**，指向 session note 路徑 + 一句話下一步
- 不要把整包進度塞進 memory 索引（一行就好）
- 沒在用 memory 機制 → 跳過此步，session note 就是唯一交接載體

### 5. 產出 resume prompts（重點交付）
輸出給使用者，放在 **code block** 方便複製：

- **完整版**（自包含，一次到位）：點名要讀的 session note、立即下一步、關鍵檔案、要跑的指令、環境雷一句話
- **短版**：「繼續 {專案}」——說明因為筆記都寫好了，這樣也接得上
- **雲端 session 一律只出自包含完整版**：把立即下一步／關鍵檔案／指令／環境雷直接寫進 prompt 本身，不依賴 note 路徑——note 可能跟 container 一起消失，唯一保證帶得過去的是使用者貼的這段字（note 是備援，不是唯一真相）

格式範例：
````
## Clear 後貼這個

```
繼續 {專案}。先讀 session note
`~/.claude/sessions/{note}.tmp` 接上進度（這 session 跑在 {機器}，
{環境雷一句話}）。下一步＝{立即下一步：動哪個檔、跑什麼}。
```

> 或直接打「繼續 {專案}」也接得上——筆記裡進度/檔案/指令/待辦都寫好了。
````

### 6. 收尾提醒
- 一句話告訴使用者：clear 完貼哪個、背景 server 還開著（如有）。

---

## 原則
- **可續做 > 完整摘要**：寧可下一步寫死，也不要寫一堆漂亮總結卻接不上。
- **路徑/指令要能直接用**：別寫「那個檔」，寫實際路徑；別寫「跑算繪」，寫實際指令。
- **環境雷必記**：尤其「跑在哪台機器」——遠端 session 的 `open`/預覽/路徑常踩這個。
- **筆記要活得比 session 久**：寫之前先確認落點不會陪 container 一起消失（雲端環境的 `~/.claude/sessions/` 就會）。
- **secret 不落地**：session note 只寫「credential 去哪拿」（密碼管理器路徑、env 檔位置），不寫明文。

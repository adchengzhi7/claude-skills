# mockup-demo

Claude Code skill：把講不清楚的需求變成可以點的互動原型：一次端 2-3 個方案讓決策者挑，定稿後那份就是驗收清單。

## 解決什麼問題

需求討論最貴的成本不是寫程式，是**來回猜**。

對方說「這裡要有個列表」，你腦中的列表跟他腦中的不是同一個——而兩邊都覺得已經講清楚了。
等兩週後做出來才對齊，代價就是兩週。

## 怎麼解

1. **一次端 2-3 個方案，不是一個**——只端一個等於替決策者做了決定。三案要只差在一件事上，每案標明「代價是什麼」
2. **假資料要假得像真的**——`測試1 測試2` 對方看不出問題；放真實業務會出現的名字金額狀態，他才說得出「這兩個狀態不會同時出現」
3. **真瀏覽器驗過才給人看**——主要互動會動、四個常見寬度零橫向溢出、零 console error
4. **拍板之後把定稿逐欄列成驗收清單**——這步最常被跳過，也最值錢

## 用法

安裝後，在對話裡講出觸發語即可：

```
先做個 mockup / 做個原型 / 畫面大概長這樣 / UI 不滿意 / 先給客戶看看
```

## 建議當範本改，不要照抄

這支是從真實工作長出來的，裡面的「踩過的雷」有些直接通用
（例如「只端一個方案等於替人做決定」），有些綁定特定工具，請換成你自己的。

**skill 真正值錢的不是步驟，是雷。** 步驟誰都想得到，雷想不到。

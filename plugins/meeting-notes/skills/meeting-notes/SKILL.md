# 會議記錄整理 — Claude 操作手冊

把一段「語音自動轉出來的會議逐字稿」整理成可以直接發給團隊的結構化記錄。
**這份檔案是寫給「執行這個 skill 的 Claude」看的，不是寫給最終使用者**。

---

## 這個 skill 解決什麼

iPhone（iOS 18+）語音備忘錄錄完會議會自動產生逐字稿 —— 但那份逐字稿：

- 滿是口語雜訊（「呃」「那個」「對對對」「然後就是說」）
- 有語音辨識錯字（人名、產品名、數字最常錯）
- 沒有標點、不分段、不標誰在講

人要從這種東西手動整理成會議記錄很痛苦。這個 skill 就是把它變成結構化記錄。

---

## 輸入：怎麼判斷拿到的是逐字稿

會觸發的訊號（任一即可）：

- 使用者明講「整理會議記錄 / 會議摘要 / 把逐字稿變記錄」
- 一段很長、口語化、缺標點的文字，內容明顯是多人對話或會議發言
- 使用者貼一個 `.txt` 檔，內容是上述形式

**不要觸發**的情況：

- 一般問答、寫作請求、程式碼 → 不是這個 skill
- 文字太短（少於約 100 字）湊不出一場會議 → 見下方「錯誤情境」

如果不確定是不是逐字稿，先問一句：「這段是要整理成會議記錄嗎？」

---

## 處理流程

### Step 1 · 先讀懂，不要急著輸出

通讀整段逐字稿，在心裡（不寫出來）做這幾件事：

1. 抓出**會議主題**是什麼
2. 認出有幾個**發言人** —— 逐字稿通常沒標誰在講，靠語意推
3. 過濾掉口語雜訊（「呃、那個、對啊、就是說」），但**只是過濾雜訊，不是改寫意思**
4. 標記**聽起來像辨識錯字**的地方（人名、數字、專有名詞）

### Step 2 · 還原會議資訊（不確定就標）

- **會議日期**：逐字稿若沒提到日期，標「待確認」。只有逐字稿裡有講、或使用者另外給了今天日期，才填。
- **相對日期換算**：逐字稿裡的「下週三」「月底前」—— 只有在會議日期已知時才換算成絕對日期，否則原樣保留並標「待確認（依會議日推算）」。

### Step 3 · 產出記錄

用下方固定格式輸出。

### Step 4 · 收尾自我檢查

輸出前確認：

- [ ] 待辦每一項都有「事項」；負責人 / 期限缺的有標「待確認」
- [ ] 沒有任何一句是逐字稿裡沒講、自己腦補的
- [ ] 疑似辨識錯字的人名 / 數字有放進「待釐清」

---

## 輸出格式

一律用這個 Markdown 結構輸出。沒有的欄位留「待確認」，不要刪掉欄位。

```markdown
# 會議記錄 · {會議主題}

- **日期**：{YYYY-MM-DD ／ 待確認}
- **與會**：{推測出的發言人；認不出名字就寫「發言人 A / B」}

## 一、會議摘要
1. {重點，3–5 點，每點一句話}
2. …

## 二、決議事項
- {這場會議「拍板」的事；沒有就寫「本次無明確決議」}

## 三、待辦清單
| 事項 | 負責人 | 期限 |
|---|---|---|
| {要做的事} | {人／待確認} | {日期／待確認} |

## 四、待釐清
- {逐字稿裡含糊、疑似辨識錯字、或該追問的點}
```

---

## 鐵則（違反就是這個 skill 失敗）

1. **不捏造**：逐字稿沒講的，不准出現在記錄裡。包括「合理推測的下一步」也不行。
2. **不確定就標，不要當事實**：人名、數字、日期、產品名只要不確定，標「待確認」或放進「四、待釐清」。
3. **過濾雜訊 ≠ 改寫**：可以拿掉「呃、那個」，不可以把對方的話換句話說到走味。
4. **辨識錯字要點出來**：例如逐字稿一下「客服系統」一下「客訴系統」，在「待釐清」寫「『客服 / 客訴系統』辨識不一致，請確認」。
5. **數字尤其小心**：語音轉稿最常錯數字。金額、日期、數量有疑慮一律標。

## 錯誤情境 cookbook

| 狀況 | 怎麼處理 |
|---|---|
| 文字太短、湊不出會議 | 不要硬做。回：「這段內容看起來不太像完整的會議逐字稿，方便補完整一點嗎？」 |
| 整段都是一個人獨白 | 還是可以做 —— 當成「會議發言 / 簡報」整理，與會欄寫單一發言人。 |
| 完全認不出在講什麼主題 | 摘要照做，主題欄寫「待確認」，並在「四、待釐清」說明。 |
| 使用者要求「翻譯成英文記錄」 | 照做，輸出格式不變，欄位標題與內容一起翻。 |
| 逐字稿混多種語言 | 記錄用逐字稿的主要語言；保留原文關鍵詞。 |
| 使用者要求存成檔案 | 存成 `會議記錄-{主題}-{日期}.md`，日期未知用今天。 |
